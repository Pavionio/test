# Отбор объявлений Авито: полный запуск через Docker

Репозиторий воспроизводит готовое решение задачи кандидатогенерации и создаёт `answer.csv` для `benchmark_queries.parquet`. Весь пайплайн запускается через Docker Compose: проверка переданного архива, извлечение данных, загрузка весов моделей, запуск Qdrant, построение индексов, поиск кандидатов, реранкинг и проверка итогового CSV.

## Требования

- Видеокарта NVIDIA GeForce RTX 5070 Ti с доступом из Docker.
- 32 ГБ оперативной памяти.
- Docker Engine с плагином Docker Compose и настроенной поддержкой NVIDIA GPU.
- Оригинальный `dataset.zip` с данными задания, заранее сохранённый на компьютер.
- Доступ в интернет при первом запуске для загрузки Docker-образов и весов моделей; достаточно свободного места на диске для извлечённых данных и индексов.

**Работа полного пайплайна на RTX 5070 Ti и 32 ГБ ОЗУ гарантируется при выполнении требований выше:** именно на такой конфигурации Docker-прогон был проверен. На других конфигурациях результат и потребление ресурсов не проверялись.

## Запуск

Подготовьте `dataset.zip`, склонируйте репозиторий и перейдите в его каталог. Укажите **абсолютный путь к ZIP-файлу** через `AVITO_DATASET_ZIP`.

Windows PowerShell:

```powershell
$env:AVITO_DATASET_ZIP = 'C:\путь\к\dataset.zip'
docker compose up --build --abort-on-container-exit --exit-code-from app
```

Linux:

```bash
AVITO_DATASET_ZIP=/absolute/path/to/dataset.zip docker compose up --build --abort-on-container-exit --exit-code-from app
```

Если переменная не задана, Docker Compose остановится с сообщением об ошибке до запуска сервисов. Архив подключается к контейнеру только для чтения; программа проверяет его SHA256 и извлекает три Parquet-файла в каталог репозитория. Сам пайплайн **не скачивает датасет**.

После успешного завершения файл `answer.csv` появится в корне репозитория. В нём будет по одной строке на каждый из 2 452 запросов и до 50 существующих `item_id` на строку.

При первом запуске программа скачает закреплённые версии моделей BGE-M3 и BGE Reranker v2 M3, проверит SHA256 архива, каждого Parquet-файла и весов, создаст локальные индексы и выполнит инференс. Извлечённые данные, веса, индексы и промежуточные результаты остаются на компьютере и используются при повторном запуске. Внешний API для инференса не нужен.

Qdrant запускается вторым сервисом Compose. Финальная схема ищет до 1000 кандидатов с глобальным и точным географическим поиском, оценивает пары запрос–объявление реранкером и записывает лучшие 50 идентификаторов. Исследовательские результаты приведены в [EXPERIMENTS.md](EXPERIMENTS.md).

## Описание решение:

Основные текстовые признаки — запрос и его фильтры, заголовок, параметры и описание объявления.Заголовок помогает находить прямые совпадения, а параметры и описание — услуги, которые в заголовке названы иначе или не названы вовсе. Также использовались локация запроса и объявления и флаг доставки: для запроса без доставки отдельно строится пул объявлений с точным совпадением location_id. История выборов из обучающей части служит дополнительным каналом поиска для уже встречавшихся текстов запросов.

Категория, подкатегория, цена, рейтинг, число отзывов и признаки доступности связи проверялись как признаки catboost. Категорию не использовали как жёсткий фильтр: в данных она почти не различает объявления.

Этап кандидатогенерации состоит из 5 частей: BM25 по заголовку; BM25 по заголовку, параметрам и описанию; символьный TF-IDF по заголовку; векторный поиск BGE-M3 через Qdrant; история выборов из train (Для каждого текста запроса код собирает объявления, которые выбирали по этому тексту в и сортирует их по числу выборов и затем при совпадении нормализованного запроса, добавляли как кандидата объявление). Результаты объединяются через RRF и берется топ 1000. Также есть два отдельных типа генерации кандидатов - глобальный по всем объявлениям и локальный с точным совпадением геолокации.

В качестве перереранжирования кандидатов сравнивались два варианта - сокращение кандидатов с 1000 до 150 с помощью catboost перед реранкером либо BGE Reranker v2 M3 оценивает все 1000 кандидатов напрямую. Лучшим оказался второй вариант. Применяем его к глобальным и локальным кандидатам, и добавляем добавку к скору для локальным кандидатов и берем топ 50 вариантов. Используются локально запускаемые open-source компоненты BGE-M3, BGE Reranker v2 M3, BM25S, scikit-learn, Qdrant и сatboost. Внешний API для инференса не используется. 

Разметку для проверки брал из train. Данные разделял по тексту запроса: все пары из валидационной выборки убирались из обучения, все объявления оставались. В валидационную выборку было взято 2000 запросов. На всех 2000 запросов было использовано на этапе кандидатогенерации. Оценивал [Recall@1000](mailto:Recall@1000) на этом этапе. Затем считал для финального ранжирование [Recall@50](mailto:Recall@50). 400 запросов было использовано для тюнинга параметров пайплайна и еще 200 для выбора финального алгоритма.

Вот что я обнаружил во время работы: У части выбранных объявлений слова запроса отсутствуют в заголовке. Поэтому к поиску по заголовку добавлены описание, параметры, символьный и векторный каналы. Жёсткий геофильтр повышал качество локальных кандидатов, но иногда оставлял запрос без ответа. Поэтому финальная схема объединяет локальные и глобальные объявления и для запросов с доставкой точный геофильтр не применяется. Catboost терял подходящие объявления при уменьшении количества кандидатов от 1000 до 150. Кроме того, модель, обученная на глобальных кандидатах, плохо работала с кандидатами после геофильтра. Отдельное обучение Catboost для этого режима исправило несоответствие признаков, но прямой реранкинг всех кандидатов всё равно показал лучший [Recall@50](mailto:Recall@50). Так как скорость работы не измерялась в виде сабмита, то catboost я не использовал.
